# Commonroom

A TypeScript web messaging and calling application being built in verified phases. Read [implementation_plan.md](implementation_plan.md) for the complete architecture, invariants, phase gates and exact resume state.

**Current scope: Phases 00–01.** Registration/login/logout, email verification/password reset through Mailpit, password change, session listing/revocation, unique profile usernames/display names and saved privacy preferences are implemented with real API data. Opaque cookie sessions, CSRF/origin checks, Argon2id, Mongo schema/index migrations and a durable encrypted email queue back these flows. Messaging, groups, avatars, attachments, calls and notification/moderation/retention workflows remain later phases; privacy preferences take effect in those features when implemented. Gateway and full worker readiness remain unavailable until their functional phases; the worker already processes auth email. This is not a production-ready product.

## Local setup

Install a supported Node LTS (CI pins 24.21.0; engines also accept Node >=22.13 on the 22 line), and a Linux-container Docker engine with Compose. Baseline services plan for >=4 CPUs, >=8 GiB free RAM and >=10 GiB free disk; scanner/media/telemetry need additional resources, not benchmarked. All dependency ports bind loopback. Compose is intentionally single-node, development-only with public local credentials, no Mongo authentication and no dependency TLS.

On Windows PowerShell, bootstrap **inside this checkout**, avoiding blocked npm.ps1 and global changes:

```powershell
npm.cmd install --prefix .cache/pnpm-cli --cache .cache/npm --no-audit --no-fund --save-exact pnpm@12.11.2
$env:Path = (Join-Path (Get-Location) '.cache/pnpm-cli/node_modules/.bin') + ';' + $env:Path
pnpm.cmd install --frozen-lockfile --state-dir .cache/pnpm-state
pnpm.cmd build
pnpm.cmd infra:config
pnpm.cmd infra:up
pnpm.cmd test:integration:foundation
pnpm.cmd db:migrate
pnpm.cmd dev
```

Linux/macOS: bootstrap using `npm install --prefix .cache/pnpm-cli --cache .cache/npm --no-audit --no-fund pnpm@12.11.2`, put `$PWD/.cache/pnpm-cli/node_modules/.bin` in the shell PATH, then the same `pnpm` commands. pnpm 12 uses `pnpm-workspace.yaml` for settings; dependency build scripts default denied, only esbuild and Argon2's native binding are allowed; Nest's optional postinstall is explicitly denied. Lockfile retains exact transitive versions/integrities. Minimal release-age exceptions are version-specific, generated by pnpm for chosen packages; review them on dependency updates.

Open http://localhost:5173. API on 127.0.0.1:3000, gateway foundation 3001, worker foundation 3002. Vite proxies health and API to preserve same-origin browser requests. API `/health/live` remains 200 without a DB; `/health/ready` needs writable Mongo replica primary. Phase-tagged readiness means foundation only, not messaging readiness. `/metrics` exposes process metrics on local servers; production edge must restrict it. Mailpit UI http://127.0.0.1:8025, Rabbit management http://127.0.0.1:15672 (development credentials in Compose).

`.env.example` documents validated options. Built processes can load overrides explicitly with `node --env-file=.env apps/api/dist/main.js` (and gateway/worker paths) from root. `pnpm dev` uses validated development defaults or externally set environment; it does **not** auto-load `.env`. Never add secrets to frontend `VITE_*` variables. Production mode refuses defaults, insecure transport/cookies, direct-only DB discovery and scanner bypass; production topology itself is deferred to Phase 08.

```text
pnpm build
pnpm typecheck
pnpm lint
pnpm test
pnpm test:foundation:http
pnpm infra:config
pnpm infra:up
pnpm test:integration:foundation
pnpm db:migrate
pnpm auth:benchmark
pnpm test:integration:auth
pnpm exec playwright install chromium
pnpm test:e2e:auth
pnpm infra:media
pnpm infra:scanner
pnpm infra:down
```

`infra:up` initializes a Mongo replica set, starts baseline dependencies, creates private Garage quarantine/approved buckets and grants only the development storage identity. Repeated start must preserve volumes. `infra:down` does not remove volumes. Optional media/scanner commands do not claim calling/scanning integration exists; media networking, provider API health, scanner signatures and isolation are later acceptance gates. Standard tests require built shared packages; `build` comes first on a fresh checkout. Real integration tests fail on missing services; no in-memory Mongo substitute or silent skip.

CI includes frozen installation/build/typecheck/lint/unit/HTTP, Compose/service/transaction checks, migration/auth integration, Chromium auth tests and high-severity production dependency audit. No remote CI run is claimed from local execution. Load/fault harnesses and later browser suites remain planned.

Register at `/register`, sign in at `/login`, and manage profile/sessions at `/account`. Start the worker (`pnpm dev` includes it) so verification/reset mail appears in local Mailpit. Follow each one-use email link; its fragment is removed from the visible URL immediately and kept only in memory. Refreshing a link page requires reopening the email. Production cookies are Secure/HttpOnly/SameSite with `__Host-` prefix; development HTTP uses an explicitly non-Secure cookie. Sessions last 7 days initially; one-use links last 30 minutes. See [auth runbook](docs/runbooks/auth.md) for rate limits, revocation, email retries and secret rotation.

For browser tests, set `PLAYWRIGHT_BROWSERS_PATH` to the workspace `.cache/ms-playwright` **before** `pnpm exec playwright install chromium`; the runner defaults to this cache. On PowerShell: `$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.cache/ms-playwright'`. Tests start their own API/worker/web processes on 3000/3002/5173; stop your own dev run first. They use a unique isolated database, real Mailpit and two independent browser contexts, then remove the test DB. Synthetic Mailpit messages can remain locally until expiry; test evidence never includes production mail or accounts.

Development fixtures: provide `SEED_PASSWORD` in the process environment and run `pnpm seed:development`. This registers `alice_dev@example.test` and `bob_dev@example.test` as ordinary accounts; verify their local emails or request a password reset through Mailpit. Existing fixture registrations are preserved and their password is not overwritten; reset if needed. The command rejects non-development mode and has no privileged seed credentials. A local seed smoke already created these two accounts with a generated process-only password; use the reset flow to choose your own password.
