## Corrections and remaining limits

Corrected implementation attempts: duplicate reserve digest discriminator, inherited method name collision, actual configured attachment count constant, DTO naming, consistent transaction snapshot for orphan protection, approved-object HEAD before granting, control-byte checks without lint violations or a 25M-element text array. First processor lock attempt accidentally contained a local root dependency; regenerated from the standalone manifest and removed the extraneous entry. Docker image built successfully with the corrected lock. Internal-only Docker networking made direct published-port host access fail; the fixed-route proxy resolved reachability while preserving decoder isolation. The old messaging negative assertion was updated from unsupported files/400 to unknown ready-file IDs/409, retaining rejection. Initial expiry assertion assumed 403 and too-short timing; actual Garage rejects expired signatures with 400, now tested with a five-second URL. Expected Vite socket abort warnings occurred during browser network/disconnect drills; browser results are authoritative, and no URL/body credentials were printed by these assertions.

Browser coverage does not separately certify midstream upload cancellation, every retry-control branch, all eight-file combinations, or the complete accessibility/browser matrix; these controls are implemented, with broader UI audit in 09.

Initial UI screenshots revealed an outdated “attachments unavailable” footer; corrected before final captures. Captures were visually inspected for usable controls, wrapping and mobile horizontal overflow. This is Chromium desktop/mobile smoke, not a complete accessibility/browser matrix.

Unverified/deferred: production storage IAM role separation (local API/worker share the development storage identity), production TLS/network/kernel hardening, image OS vulnerability scanning, resource/concurrency/capacity SLOs, remote CI, rolling upgrades, backup restore, actual provider disaster recovery, antivirus false negatives/signature freshness alerts, broader accessibility and browser matrix. Metadata/action/tombstone retention, account deletion and notifications/moderation are Phase 06/08. Avatar upload remains unimplemented and is explicitly tracked for Phase 09 with appropriate profile visibility policy; the historical Phase 01 “until 05” note is superseded. Calls remain Phase 07. No full Telegram feature parity or application E2EE is claimed.
