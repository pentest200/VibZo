# Messaging interface

Commonroom's interface follows Telegram Web's full-height chat layout. It keeps Commonroom's own accounts and supported features. Sign in, verify your email, then choose **Open conversations** at the top of Account settings. In local development verification emails appear in Mailpit, not an external mailbox.

The sidebar shows real conversations and invitations. Choose **All chats** or **Unread** to filter it. Each chat's more-options control offers private **Pin chat** and **Archive chat**. Pinned chats sort first; **Archived chats** opens the separate folder, where **Unarchive chat** returns them. These preferences sync across your devices and never change someone else's inbox. Archive remains until explicitly undone. Drag the desktop divider to resize the list; keyboard arrows/Home/End also work and double-click resets it. Only validated width and appearance preferences are stored in localStorage; credentials/chat data are not. Mobile remains one pane. **Search people**, the pencil button, or **New message** opens username discovery; enter at least three username characters. **New group** opens group creation. The menu opens Account & privacy and Night mode; Escape closes it and restores focus.

Select a conversation to open its actual history. On narrow screens the chat replaces the sidebar; the back arrow returns to the list. Select the header avatar or more-options button to open conversation information. Group managers use Group settings there to rename, invite and manage members. Close the panel to return to the chat on mobile.

Type in the bottom message field; **Enter** sends and **Shift + Enter** inserts a new line. IME composition does not trigger Enter-to-send. The smile button opens all 3,953 qualified Unicode 17 emoji/components with search, categories and skin tones; selection inserts ordinary text at the cursor. Glyph artwork/support follows your OS. The paperclip opens scanning/status and ready-file selection; Escape closes popovers. Message options reveal reply/edit/delete/pin/reaction/report inside the bubble. **Edit message** uses the composer; Save/Enter saves, Cancel/Escape restores your draft. **Delete message** opens an app dialog with **Delete for me** and, for your own messages, **Delete for everyone**. Personal deletion hides only your copy across devices; other participants keep theirs. Reports use a contained dialog. **Pin message** shares an authorized pin; group changes require admin/owner. The pinned bar opens current accessible pins, including older messages; clear/history/membership restrictions still apply.

Read receipts are automatic. A single tick means server acceptance, a double tick means delivery, and a blue double tick means read. Group indicators mean at least one eligible peer. Reading advances when the active history is actually visible in a focused document; off-screen messages and messages covered by a modal/details overlay do not count. Delivery/read remain account-level monotonic receipts. Pending offline commands are separate from server acceptance; there is no manual mark-read button.

The conversation list scrolls independently beneath its search/filter header. Conversation details contain **Clear chat history**, **Delete chat** for direct chats, and owner-only **Delete group**. Each has an explicit confirmation. Clear history affects only your earlier history across devices. Delete chat also hides that direct chat; a new message or explicit contact reopening restores it. Group deletion ends everyone's access and schedules private-file/call cleanup. Other people's history is unchanged by your personal clear/delete action.

Ready photos/GIFs render directly in message bubbles; video/audio show native playback controls there. Private grants load near the viewport with at most three requests at a time. Click an image or expand a player for a larger in-app view; expanding pauses inline playback. Escape closes the expanded player and stops it. Icon downloads remain available; Reload requests fresh access if a grant expires or playback fails. No autoplay is used. Photos normalize to WebP; GIF animation remains. MP4/WebM and MP3/WAV/Ogg playback depends on native codecs (audio WebM uses the WebM player). PDF/text remain downloads. Never bypass scanning to preview staged files.

Unconfirmed sends and failed commands remain visible with their retry/discard controls. Transient background receipt/reaction commands remain in the same durable engine without filling the composer with processing records. Positive acceptance is announced to assistive technology; canonical bubbles and receipts provide the normal visual feedback. Storage failures remain visible.

Voice/video buttons use the configured actual provider; unavailable calling stays disabled with an explanatory tooltip. Incoming calls remain visible from the mobile inbox. Opening/accepting a call presents a full-screen in-app window. Its back button or Escape minimizes it to a small rectangle below the chat header; messaging stays usable and media stays connected. **Expand call** restores the same session. Leaving, ending or stopping media still releases tracks through the existing controls. An ongoing call replaces redundant start buttons with **Open current call**. The clock icon opens actual call history after closing/minimizing the full-screen view. A terminal call can be closed after the server confirms its final state. Account settings retain profile/privacy, the actual private avatar, devices, password recovery, notifications, moderation and deletion. An unverified account gets an explicit explanation of how to unlock chat.

See [redesign evidence](../ui-redesign-evidence.md), [chat-experience follow-up](../chat-experience-evidence.md) and [current message interactions](../message-interactions-evidence.md) for executed gates and limitations. This layout does not add Telegram channels, bots, stickers, voice-note recording or end-to-end encryption. Manual assistive-technology/physical-device and production gates remain separate.
