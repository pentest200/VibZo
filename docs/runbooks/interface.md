# Messaging interface

Commonroom's interface follows Telegram Web's full-height chat layout. It keeps Commonroom's own accounts and supported features. Sign in, verify your email, then choose **Open conversations** at the top of Account settings. In local development verification emails appear in Mailpit, not an external mailbox.

The sidebar shows real conversations and invitations. Choose **All chats** or **Unread** to filter it. **Search people**, the pencil button, or **New message** in the main menu opens username discovery; enter at least three username characters and choose the person to open a direct chat. **New group** opens group creation. These panes focus their input for keyboard use. The menu also opens Account & privacy and toggles Night mode. Only the versioned, non-sensitive light/dark preference is stored in localStorage; it survives reload. If storage is denied, appearance remains usable for the current page. Credentials and chat data are not stored there. Escape closes the main menu and returns focus to its trigger.

Select a conversation to open its actual history. On narrow screens the chat replaces the sidebar; the back arrow returns to the list. Select the header avatar or more-options button to open conversation information. Group managers use Group settings there to rename, invite and manage members. Close the panel to return to the chat on mobile.

Type in the bottom message field; **Enter** sends and **Shift + Enter** inserts a new line. IME composition does not trigger Enter-to-send. The smile button inserts emoji as ordinary message text. The paperclip opens file selection, scanning status and selection of ready attachments; safety checks and file restrictions still apply. **Escape** closes the composer popovers. Reply, edit, delete, reactions and reporting retain their existing authorized behavior. Desktop message actions appear on hover or keyboard focus; touch layouts expose them beneath the message. Receipt/read actions show the server's actual state, not inferred delivery guarantees.

Unconfirmed sends and failed commands remain visible with their retry/discard controls. Transient background receipt/reaction commands remain in the same durable engine without filling the composer with processing records. Positive acceptance is announced to assistive technology; canonical bubbles and receipts provide the normal visual feedback. Storage failures remain visible.

Voice/video buttons use the configured actual provider; unavailable calling stays disabled with an explanatory tooltip. Active/incoming calls use a separate dock that remains visible from the mobile inbox as well as a selected conversation. An ongoing call replaces redundant start buttons with **Open current call**. The clock icon opens actual call history. A terminal call panel can be closed after the server confirms its final state. Account settings retain profile/privacy, the actual private avatar, devices, password recovery, notifications, moderation and deletion. An unverified account gets an explicit explanation of how to unlock chat; verification is never bypassed by the interface.

See [redesign evidence](../ui-redesign-evidence.md) for executed gates and limitations. This layout does not add Telegram channels, bots, stickers, voice-note recording or end-to-end encryption. Manual assistive-technology/physical-device and production gates remain separate.
